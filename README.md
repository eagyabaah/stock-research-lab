# Stock Research Lab

A runnable Streamlit website for transparent US swing-trade qualification and
Ghana long-term stock scoring. It implements the mandate we defined:

- $1,000 initial portfolio and $500 monthly contribution context;
- 10% drawdown halt;
- $5 initial US risk per trade and $20 maximum concurrent open risk;
- $200 maximum US position;
- 2:1 minimum reward/risk;
- no leverage or averaging down; US analysis now evaluates long, short, and no-trade outcomes. Option-contract analysis remains a later layer; Ghana remains long-term only;
- no Ghana swing trading.

The site shows the evidence behind every gate. It does **not** expose or depend
on hidden model reasoning, and it does not place orders.

## Features

- Dedicated full-report search for any supported US-listed ticker, including RDW.
- Batch screen of up to eight US tickers.
- Direction-neutral conclusion: STRONG LONG, LONG, STRONG SHORT, SHORT, or NO TRADE.
- Separate Long and Short 100-point scores, each with independent hard gates.
- Short-specific squeeze-risk check using short interest and days-to-cover when available.
- SPY market-regime gate.
- Trend-pullback, confirmed-breakout, and recovery/reclaim strategies.
- SMA20/50/200, RSI14, ATR14, volume ratio, 20-day breakout level, and 63-day
  relative strength.
- Fundamentals, valuation, news/event, liquidity, and risk gates.
- Entry, stop/invalidation, 2R/3R/4R targets, risk per share, reward/risk, fractional shares, notional, and planned maximum loss for the selected direction.
- Portfolio drawdown and existing-open-risk breakers.
- Candlestick chart with model levels.
- Evidence, bull thesis, bear case, and invalidation conditions.
- Automated Ghana long-term research for supported GSE tickers, with delayed
  price, growth, profitability, valuation, cash-flow, liquidity, 200-day timing,
  GSE/SEC headline screening, source dates, and links for every populated field.
- JSON export of each report.
- Weekday post-close reports generated by GitHub Actions and displayed in the website.

## Run locally

Use the same supported Python version locally and in deployment. This project is
tested by its automated suite and configured to deploy on Python 3.12.

```bash
python -m venv .venv
```

On macOS/Linux:

```bash
source .venv/bin/activate
```

On Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Install and launch:

```bash
pip install -r requirements.txt
streamlit run app.py
```

Open `http://localhost:8501` if it does not open automatically.

## Run with Docker

```bash
docker build -t stock-research-lab .
docker run --rm -p 8501:8501 stock-research-lab
```

Then open `http://localhost:8501`.

## Deploy as a public website

The simplest path is Streamlit Community Cloud:

1. Put this folder in a GitHub repository.
2. Sign in at `share.streamlit.io`.
3. Choose **Create app**, select the repository, and set `app.py` as the entrypoint.
4. Deploy and use the assigned `streamlit.app` URL.

## Turn on weekday closing reports

The included `.github/workflows/closing-report.yml` workflow runs at 22:00 UTC
Monday through Friday, after the US regular session in both daylight and standard
time. It analyzes the symbols in `watchlist.txt` and the long-term GSE symbols in
`ghana_watchlist.txt`, then commits the US and Ghana report files for the website.

After uploading this version to GitHub:

1. Open the repository's **Settings → Actions → General**.
2. Under **Workflow permissions**, select **Read and write permissions** and save.
3. Open the repository's **Actions** tab and enable workflows if GitHub asks.
4. Select **Weekday closing stock report**, click **Run workflow**, and run it once.
5. When the run finishes, confirm `reports/latest.json` exists. Streamlit will
   redeploy automatically after the workflow commit.

Edit `watchlist.txt` or `ghana_watchlist.txt` in GitHub whenever you want to change
the corresponding scheduled list.
The workflow does not need an API secret.

GitHub schedules can start several minutes later than the exact cron time. The
job also runs on exchange holidays and will label the report when the latest
trading date is older than the run date.

The included `Dockerfile` also works with hosts that accept containers.

## Tests

The strategy-engine tests use only Python, pandas, and NumPy; they do not call a
live data source:

```bash
python -m unittest discover -s tests -v
```

## Data and safety

The default adapter uses the community-maintained `yfinance` package. Its own
documentation describes it as an open-source research/personal-use interface,
not an official Yahoo product. Therefore:

- treat prices as research data, not executable quotes;
- confirm entries and position sizes in Robinhood;
- verify earnings and financial data in company filings;
- review every flagged article instead of trusting keyword sentiment;
- treat the automated Ghana data as delayed research data, review the linked GSE
  and SEC evidence, and use the actual IC Wealth quote as the executable price.

The Ghana adapter caches requests for six hours and retrieves public research
pages only when you click **Run Ghana long-term analysis**. If a page or official
review is unavailable, the affected evidence stays `Unknown`; it is never changed
to a pass. Ghana output remains long-term accumulation only.

The scheduled website report uses deterministic market-data and headline rules.
It cannot independently browse and cross-check primary sources with the same
depth as a human or research assistant. Treat its headline links as a research
queue, not as proof that every material event was found.

The directional layer now evaluates both sides. A short plan may be generated
when the short hard gates pass, but broker locate/borrow availability is not
verified by the current adapter and must be confirmed at execution.

See `MODEL_RULES.md` for the exact scoring rules and limitations.
